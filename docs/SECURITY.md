# الصلاحيات والحماية

## الأدوار

| | زائر غير مسجّل | طالب | أدمن |
|---|:-:|:-:|:-:|
| فتح صفحات المنصة | ✗ (يُحوَّل للدخول) | ✓ | ✓ |

## كيف تُفرض الحماية

الحماية الحقيقية في **Supabase (RLS)** وليس في واجهة المتصفح، لأن أي شخص يستطيع تعديل كود المتصفح.
ملف `supabase/schema.sql` ينشئ:

- جدول `profiles` (الاسم، البريد، الدور) ينشأ تلقائياً عند التسجيل بدور `student`.
- دالة `is_admin()` تتحقق من الدور.
- سياسات `submissions`: الجميع يقرأ المعتمد فقط، الطالب يُدرج بحالة `approved = false` فقط، والأدمن يفعل كل شيء.
- سياسات Storage (1.2.0): الطالب يرفع إلى bucket خاص `pending-uploads` داخل مجلده `<uid>/` فقط (25MB وأنواع محددة)، والأدمن وحده يقرأ الملفات المعلّقة (روابط موقّعة) ويحذفها، ونقل الملف إلى `Twix/approved/` للأدمن فقط.
- جدول `submissions`: الإدراج يفرض `user_id = auth.uid()` و`approved = false` ومساراً داخل مجلد الطالب؛ ولا يمكن للطالب كتابة رابط خارجي أو `javascript:`.
- روابط الملفات تمر عبر `safeHref` (حماية من XSS)، والروابط الخارجية القديمة تُفتح بعد تأكيد الأدمن.
- `activity_log` عليه حدّ معدّل 300 حدث/ساعة لكل مستخدم.

## ⚠️ مراجعة السياسات القديمة (مهم)

النسخة القديمة كانت تعتبر أي مستخدم مسجّل أدمن، فقد توجد سياسات قديمة تسمح لأي `authenticated` بالتعديل أو الحذف. بعد تشغيل `schema.sql`:

```sql
select schemaname, tablename, policyname, cmd, roles
from pg_policies
where tablename in ('submissions', 'objects', 'profiles')
order by tablename, policyname;
```

احذف أي سياسة قديمة (غير التي أنشأها `schema.sql`) تسمح لأي مستخدم مسجّل بـ `update` أو `delete` على `submissions`، أو `delete` على `storage.objects`:

```sql
drop policy "اسم_السياسة_القديمة" on public.submissions;
```

السياسات تتجمّع بمنطق **OR**: وجود سياسة واحدة متساهلة يكفي لفتح الباب.

## المفاتيح

- المفتاح العام (`sb_publishable_...` / anon) مصمم ليظهر في المتصفح، ولا بأس بوجوده في الكود.
- مفتاح `service_role` **سري**: لا يوضع في الكود ولا في متغيرات `NEXT_PUBLIC_` ولا في GitHub أبداً.

## ملفات التخزين عامة

الـ bucket `Twix` عام، فأي شخص لديه رابط ملف يستطيع فتحه حتى بدون حساب. هذا مناسب للمحاضرات العامة. **لا تضع فيه مواد سرية** (مثل امتحانات رسمية قبل موعدها).
وإن احتجت ملفات خاصة لاحقاً، نستخدم bucket خاصاً مع روابط موقّتة.

## تأكيد البريد والتسجيل

- **Confirm email** معطّل افتراضياً هنا (لأن SMTP الافتراضي محدود)، فيمكن لأي شخص التسجيل ببريد لا يملكه. مقبول لمنصة صغيرة؛ لتشديده فعّل SMTP مخصصاً ثم Confirm email.
- لإيقاف التسجيل مؤقتاً: Authentication ← Sign In / Providers ← عطّل **Allow new users to sign up**.

## الخصوصية

بحث الطلاب بالاسم متاح للأدمن فقط. الطالب لا يرى أي طالب آخر.

## الـ Edge Functions والمساعد الذكي

راجع قسم «الأمان» في [API.md](API.md): التحقق من الهوية والأدمن على السيرفر، إبقاء المفاتيح السرية خارج المتصفح، الحد اليومي للمساعد، وجدول `notifications` الذي لا يُدرج فيه إلا السيرفر (الطالب يقرأ إشعاراته فقط ويعلّمها كمقروءة).

## الإحصاءات

جدول `activity_log` يسجّل (مادة/ملف/نوع النشاط/معرّف الطالب). الطالب يُدرج نشاطه فقط ولا يقرأ الجدول، والأدمن يرى **أرقاماً مجمّعة** فقط عبر الدالتين `stats_by_subject` و`stats_top_files` (لغير الأدمن ترجعان فارغتين). لا تُعرض للأدمن أي قائمة بما فعله طالب بعينه.
